# Windows Deep Cleaner — Technical Internals & Forensics Matrix

A comprehensive reference of the file paths, registry keys, and system artifacts managed by **Windows Deep Cleaner (WDC)**.

---

## 🔬 Filesystem Artifacts & Systems Rationale

### 1. Windows Prefetch (`%SystemRoot%\Prefetch`)
- **Format**: SCCA format with OS-specific headers (v23 for Win7, v30 for Win10/11).
- **Function**: Generated by the Windows Cache Manager when an executable launches. Stores file path references, loaded DLLs, execution count, and last execution timestamps.
- **Cleanup Rationale**: Obsolete entries from uninstalled tools, portable executables, and transient installers persist indefinitely. WDC purges stale `.pf` files; Windows regenerates optimal hash entries for active applications on subsequent runs.
- **Red Team / Forensics Context**: Prefetch is a primary evidence source in DFIR for proving binary execution and intrusion timelines.

### 2. Explorer JumpLists & Recent Items (`%AppData%\Microsoft\Windows\Recent`)
- **Format**: 
  - `*.lnk`: Shell link binary format (`[MS-SHLLINK]`).
  - `AutomaticDestinations`: OLE Compound File (CFBF) format tracking application usage.
  - `CustomDestinations`: Application-pinned destination lists.
- **Function**: Maintained by the Windows Shell to track recently opened files and application actions for the Start menu and Taskbar JumpLists.
- **Cleanup Rationale**: Preserves privacy by wiping local access history and file traces.

### 3. DirectX & GPU Driver Shader Caches
- **Paths**:
  - `%LocalAppData%\D3DSCache` (DirectX HLSL compiled bytecodes)
  - `%LocalAppData%\NVIDIA\DXCache` (NVIDIA graphics driver shader cache)
  - `%LocalAppData%\AMD\DxCache` (AMD Radeon driver shader cache)
- **Function**: Precompiled shader binaries stored to reduce in-game compilation overhead.
- **Cleanup Rationale**: Shader caches do not automatically garbage-collect. Over time, outdated driver versions leave multi-gigabyte orphaned blobs that can cause shader pipeline corruptions and micro-stutters in DirectX 11/12 games. Drivers cleanly recompile fresh shaders upon next launch.

### 4. Windows Error Reporting (WER) & Crash Dumps
- **Paths**:
  - `%LocalAppData%\CrashDumps`
  - `%ProgramData%\Microsoft\Windows\WER\ReportArchive`
  - `%ProgramData%\Microsoft\Windows\WER\ReportQueue`
  - `%ProgramData%\Microsoft\Windows\WER\Temp`
- **Function**: Generated during application crashes and unhandled exceptions (`MiniDumpWriteDump`).
- **Cleanup Rationale**: Crash dumps (`.dmp`) consume substantial disk space and can contain memory fragments, environment variables, or sensitive string data loaded into process memory at crash time.

### 5. Windows Update & Delivery Optimization
- **Paths**:
  - `%SystemRoot%\SoftwareDistribution\Download`
  - `%SystemRoot%\SoftwareDistribution\DeliveryOptimization`
- **Function**: Staging directory for cumulative updates, definition files, and peer-to-peer LAN distribution chunks.
- **Cleanup Rationale**: Downloaded `.cab` and `.esd` installation payloads often remain cached after updates are successfully installed. Stopping `wuauserv` and `bits` allows clearing these stagnant payloads safely.

### 6. User & System Temporary Directories
- **Paths**:
  - `%temp%` (`%LocalAppData%\Temp`)
  - `%SystemRoot%\Temp`
- **Function**: Scratch space for decompression, MSI installers, and runtime logging.
- **Cleanup Rationale**: Most installers fail to clean up their unpacked archives. WDC recursively purges temp trees and skips open handles held by running processes (`>nul 2>&1`).

### 7. Recycle Bin Metadata & Storage
- **Paths**: `$Recycle.Bin\<User-SID>` across all attached partitions.
- **Function**: Contains paired `$I` (metadata header containing deletion time and original path) and `$R` (actual file contents) records.
- **Cleanup Rationale**: Standard desktop GUI empties only the current partition. WDC iterates over all logical volumes using WMI/PowerShell to ensure complete removal across secondary and external drives.

## ⚙️ Native VolumeCaches Automation (`cleanmgr.exe`)

WDC pre-configures registry state flags (`StateFlags0064 = 2`) under:
```registry
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\VolumeCaches
```

This triggers Windows' low-level kernel cleanup handlers via:
```cmd
cleanmgr.exe /sagerun:64
```

Configured targets include:
- `Active Setup Temp Folders`
- `Delivery Optimization Files`
- `Diagnostic Data Viewer database files`
- `Downloaded Program Files`
- `Internet Cache Files`
- `Old ChkDsk Files`
- `Previous Installations` (`Windows.old`)
- `Recycle Bin`
- `RetailDemo Offline Content`
- `Setup Log Files`
- `System error memory dump files`
- `System error minidump files`
- `Temporary Files`
- `Temporary Setup Files`
- `Thumbnail Cache`
- `Update Cleanup`
- `Upgrade Discarded Files`
- `Windows Defender Temp Files`
- `Windows Error Reporting Files`
- `Windows Upgrade Log Files`

## 🛡️ Safety Verification

1. **Read-Only Scope for User Data**: WDC strictly targets disposable transient directories. User data roots (`Documents`, `Desktop`, `Pictures`, `Music`, `Videos`, `Downloads`) are excluded.
2. **Handle-Safe Deletion**: Deletion routines use non-blocking flags. If a file is locked by an active process (such as a running browser session), the command skips it gracefully without halting execution.
3. **No Dynamic DLL Loading**: WDC relies entirely on native Windows command-line binaries, eliminating DLL hijacking vectors and third-party dependency vulnerabilities.
